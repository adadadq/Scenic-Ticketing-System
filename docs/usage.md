# 使用说明

## 游客端

### 注册与登录

1. 打开 `/#/visitor/booking`。
2. 点击右上角“登录”。
3. 已有账号填写账号和密码；新用户切换到“注册账号”，填写 3-32 位账号、至少 6 位密码和手机号。
4. 登录后可查看自己的订单和维护常用出行人。

### 购票与支付

1. 选择票种。
2. 选择游览日期和可售时段。
3. 在“填写信息”阶段选择已有常用出行人，或点击“新增出行人”填写姓名、证件类型、证件号和手机号。
4. 为每张票分配出行人并核对订单摘要。
5. 点击底部主按钮创建订单，进入订单确认后完成模拟支付。
6. 支付成功后到“我的订单”查看票码和入园信息。

### 订单与退款

1. 打开 `/#/visitor/orders` 并登录。
2. 可按全部、待支付、已支付、已退款、已取消筛选。
3. 待支付订单可继续支付或取消。
4. 已支付且仍在退票期限内的订单会显示退款入口；确认原因后提交退款。
5. 退款成功后订单、支付和票项状态变为“已退款”，退款审计记录为游客操作。

已超过退票期限、存在已核销票项或不满足退款规则时，系统会拒绝自助退款，需要联系景区工作人员。

### 游客服务

`/#/visitor/service` 展示开放时间、售票与入园时间、客服信息、路线和退改说明。

## 管理端

1. 打开 `/#/admin`，使用管理员账号登录。
2. 票种管理：新增、编辑、上下架票种；所有写操作进入审计日志。
3. 系统设置：维护景区名称、营业时间、单笔限购和安全开关。
4. 订单管理：检索订单、查看明细、整单/部分退款。
5. 核验入园：按票码核销、批量核销或撤销核销。
6. 审计与报表：查看核销、失败、退款和设备审计，导出 CSV/XLSX。
7. 公告：发布后会同步显示在游客购票页。

退款属于高风险操作，仅具备对应权限的管理员可以执行。

## 常见问题

- “登录状态检查失败”：先检查 `/api/health` 和 `/api/health/db`，再确认前端与 API hostname 一致。
- “服务暂时不可用”：通常是数据库连接、迁移未执行或后端依赖版本不匹配。
- 找不到支付按钮：先完成票种、时段和出行人分配，底部主按钮会进入订单确认/支付。
- 常用出行人保存失败：确认已登录、证件号格式正确，并检查数据库是否已执行 `2026-07-09-add-passenger-templates.sql`。
- 游客退款认证失败：确认已登录当前订单所属账号，并执行 `2026-07-13-add-visitor-refund-audit-actor.sql`。
