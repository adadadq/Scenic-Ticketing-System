## 3. 全局视觉规则

- 使用浅色运营工作台风格。
- 主色为水绿 / 青绿，表达遇龙河和码头业务识别。
- 橙色只用于价格、待支付、告警和关键状态。
- 主要卡片半径为 8px。
- 少用阴影，更多依赖边框、分隔线和留白建立层级。
- 信息密度偏高，但表单和移动端不能拥挤。
- 图标使用 Ant Design Icons，不混用多个图标体系。
- 页面第一屏必须是可操作业务界面，不做营销式 hero。

禁止：

- 不使用深色发光背景。
- 不使用渐变光斑、装饰性圆球、大片 stock 背景图。
- 不做卡片套卡片。
- 不让按钮文字换行。
- 不把 imagegen 中的错误品牌、随机小字、随机功能照抄进实现。

## 4. 页面 1：登录 / 实名注册

设计稿：

```text
docs/frontend/mockups/auth-realname-entry-v1.png
```

页面目标：

- 让游客快速进入系统。
- 解释为什么需要实名。
- 告知未登录、未实名、已实名三种状态能做什么。
- 暴露 CSRF / 安全提示，但不吓人。

布局：

- 顶部简洁品牌栏：遇龙河票务系统、帮助入口。
- 左侧为流程解释和实名理由。
- 右侧为登录 / 实名注册表单。
- 底部或表单下方展示登录状态说明。

组件映射：

- `Layout` / 自定义 entry shell。
- `Card` 承载说明区和表单区。
- `Steps` 展示“游客进入 -> 实名认证 -> 开始购票”。
- `Form`、`Input`、`Select`、`Checkbox`、`Button`。
- `Alert` 展示 CSRF / 安全提示。
- `Tag` 或小状态点展示账号状态。

采用：

- 左侧实名解释和安全说明。
- 右侧登录与实名注册切换。
- 登录状态说明区。
- 清晰的主按钮和次按钮。

不采用：

- 真实短信验证码服务。MVP 不接短信服务，手机号登录可用演示输入或本地验证码占位。
- 随机协议链接内容。实现时只保留占位链接或本地说明。

状态：

- loading：提交按钮显示加载。
- error：表单上方展示统一错误。
- success：登录后跳转购票工作台。
- disabled：未勾选确认时禁用提交。

## 5. 页面 2：游客购票工作台

设计稿：

```text
docs/frontend/mockups/visitor-booking-workbench-v1.png
docs/frontend/mockups/visitor-booking-workbench-v2.png
```

页面目标：

- 让实名游客完成购票主流程。
- 让临时游客可浏览，但不能下单。
- 清楚展示票种、日期、时段、数量、金额和模拟支付入口。

布局：

- 左侧业务导航。
- 顶部状态栏。
- 主工作区分为购票步骤和选择内容。
- 右侧固定订单摘要。
- 下方可放系统状态或更新时间。

组件映射：

- `Layout.Sider`、`Layout.Header`、`Layout.Content`。
- `Steps`。
- `Table` 或 `Radio.Group + List` 展示票种。
- `DatePicker` 或自定义日期条。
- `Segmented` / `Radio.Button` / `Card` 展示时段。
- `InputNumber` 设置数量。
- `Descriptions` 或自定义 summary panel 展示订单摘要。
- `Button` 执行模拟支付。

采用：

- 订单摘要右栏。
- 票种表格。
- 日期和时段区域分层。
- 价格使用橙色。
- 可售状态使用小圆点和文字。
- v2 中的未实名门槛：临时游客可以浏览票种和时段，但订单摘要主按钮禁用，并给出“先实名再下单”的明确入口。
- v2 中的顶部健康和会话状态：API、数据库、会话和 CSRF 使用小 Badge，不做大面积告警。
- v2 中的右侧摘要信息层级：票种、游览信息、游客信息、金额明细、安全提示依次排列。

不采用：

- 错误品牌文字。
- 过多后台导航项。MVP 只保留“游客购票”和“我的订单”，后台项后续阶段再显示。
- 不可读的小型说明文字。
- v2 中任何截图式固定宽度。实现时右侧摘要在中等桌面以下进入下方堆叠或抽屉。
- imagegen 生成的随机具体百分比库存文案。真实余票状态只使用后端返回的 `quotaRemaining` 计算展示。

状态：

- 未登录：展示登录引导。
- 临时游客：可浏览，提交下单时提示需要实名。
- 已实名：允许下单。
- 无票种：展示 `Empty`。
- 无时段：展示空态和换日期提示。
- 库存不足：时段禁用或展示警告。

## 6. 页面 3：我的订单 / 订单详情

设计稿：

```text
docs/frontend/mockups/my-orders-detail-v1.png
docs/frontend/mockups/my-orders-contract-states-v2.png
docs/frontend/mockups/visitor-orders-mobile-v1.png
```

页面目标：

- 游客查看自己的订单。
- 待支付订单可以继续支付或取消。
- 已支付订单展示票码。
- 已取消订单只读展示。

布局：

- 左侧复用业务导航。
- 主区域为订单标题、状态筛选、搜索/日期过滤、订单表格。
- 右侧为订单详情面板。
- 小屏下详情面板变为抽屉或详情页。

组件映射：

- `Tabs` 或 `Segmented` 做状态筛选。
- `DatePicker.RangePicker`。
- `Input.Search`。
- `Table`。
- `Tag` 展示订单状态。
- `Drawer` 或右侧 `Card` 展示订单详情。
- `Descriptions` 展示订单信息。
- `Button` 做继续支付、取消订单。

采用：

- 状态筛选。
- 订单表格和右侧详情并列。
- 待支付倒计时提示。
- 票码区域按状态展示。
- 底部固定操作按钮。
- v2 中的契约错误块：订单详情查询失败、不可取消、不可支付等错误必须显示业务错误文案、错误码和请求编号。
- v2 中的票码区域：已支付订单展示按游客拆分的票码/取票凭证；待支付和已取消订单不展示可入园票码。
- v2 中的只读状态：已取消订单只允许查看详情，不出现支付和取消操作。
- 移动端 v1 中的订单卡片：显示状态标签、票名、日期、时段、数量、金额和订单时间，并用详情抽屉承接继续支付、取消、重新购票等状态动作。
- 移动端 v1 中的契约状态：订单加载失败、暂无订单、未登录均要有独立块；错误块可重试且保留错误码和请求编号，不泄露后端堆栈。

不采用：

- 游客侧“申请退款”入口。当前退款能力只在管理员后台按契约开放整单退款；游客订单页不直接提交退款状态变更。
- 管理员相关入口。
- 过多通知和天气信息。
- v2 中的固定页码和假订单数量。实现按真实列表数据和分页策略展示。
- 移动端 v1 中的完整图片素材、固定 iOS 状态栏和随机码头地址。当前 DTO 没有产品图和码头详情字段，React 实现只保留小型景区视觉占位和已有字段。

状态：

- 空订单：展示 `Empty` 和“去购票”按钮。
- 待支付：展示继续支付、取消订单。
- 已支付：展示票码，不显示取消。
- 已取消：只读展示。
- 订单不存在或越权：展示统一错误，不泄露是否存在。

## 7. 页面 4：移动端购票流程

设计稿：

```text
docs/frontend/mockups/mobile-booking-flow-v1.png
```

页面目标：

- 在手机宽度下完整走通购票。
- 保留清晰步骤，不把桌面表格硬塞进移动端。

布局：

- 单列页面。
- 顶部简洁标题和返回入口。
- 步骤条横向展示，必要时缩短文案。
- 票种使用卡片列表。
- 日期使用横向日期条。
- 时段使用网格按钮。
- 底部 sticky 订单摘要和主按钮。
- 支付成功结果独立展示。

组件映射：

- 响应式 `Steps`。
- `List` / 自定义票种卡片。
- `Segmented` / 横向滚动日期条。
- `Button` 网格。
- `Affix` 或 fixed bottom action bar。
- `Result` 展示支付成功。

采用：

- 三屏流程：选票、选时段和游客信息、订单摘要和支付结果。
- 底部 sticky summary。
- 移动端价格和主按钮保持醒目。

不采用：

- 小程序专用胶囊按钮样式。实现是 Web，不模拟微信小程序 chrome。
- 真实风景图片作为必需元素。可用产品缩略图占位，但不能依赖外部图片。

状态：

- 小屏按钮不可换行。
- 长票种名最多两行，超出省略。
- sticky 底栏不遮挡内容，页面底部留安全空间。
- 订单摘要在支付成功后变为结果态。

## 8. 页面 5：后台运营工作台

设计稿：

```text
docs/frontend/mockups/admin-login-shell-v1.png
docs/frontend/mockups/admin-operations-workbench-v2.png
docs/frontend/mockups/admin-workbench-desktop-v3.png
docs/frontend/mockups/admin-order-detail-mutation-drawer-v1.png
docs/frontend/mockups/admin-mobile-workbench-v1.png
```

页面目标：

- 给管理员提供可扫描、可操作、可审计的运营工作台。
- 在管理员会话建立后展示报表、订单 read-model、票码核验、整单退款和退款审计检索。
- 保持前端动作与后端契约一致：状态变更走 CSRF，退款只提交 `reason`，金额和库存回补由后端计算。

布局：

- 左侧复用业务导航，新增后台管理入口。
- 未登录时主区域显示管理员登录表单、安全边界和登录错误。
- 已登录时后台使用子页面分区：`#/admin` 是运营概览和入口，`#/admin/tickets` 是票种管理页，`#/admin/reports` 是报表页，`#/admin/orders` 是订单 / 核验 / 退款页，`#/admin/audit` 是审计 / 导出页。
- v4 已登录桌面结构先在概览页展示五步运营流程和票种 / 只读 / 状态变更 / 审计导出边界条；票种新增、改价、上下架和删除只在票种页；报表总览与支付对账只在报表页并排成洞察区，订单操作台只在订单页，审计和导出只在审计页。
- 安全机制以小型状态区、Tag 和 Alert 呈现，不做大面积宣传。

采用：

- 管理员账号和密码表单。
- HTTP-only Cookie、CSRF Header、管理员会话、审计留痕四类安全提示。
- 报表 read-model、CSV 导出、订单列表、订单详情。
- 票码核验动作：只提交票码，展示错误码和请求编号。
- 整单退款动作：只提交 `reason`，可退条件为 `PAID + PAID + 全部 UNUSED`。
- 订单内退款审计日志和全局退款审计检索。
- Mock / API mode 标签，便于不等真实后端时继续前端布局和状态验证。
- 订单详情抽屉中的状态摘要、票项核验、整单退款、部分退款和退款审计分区。

不采用：

- 不新增退款审批状态机。当前只有整单退款动作和退款审计检索。
- 不展示真实管理员 id、完整手机号、证件号、SQL、session token 或密码。
- 不把 imagegen 中的随机 IP、二维码、假统计数字照抄到实现。
- 不做没有状态边界的裸操作按钮。

状态：

- 未登录：显示管理员登录表单和安全边界提示。
- Mock 已登录：显示 mock 模式标签和 mock 运营数据。
- API 已登录：显示真实管理员会话和后端返回的 read-model。
- `ADMIN_AUTH_REQUIRED` 与 `ADMIN_FORBIDDEN` 必须回到未登录 / 无后台权限状态。
- 核验、退款、报表、审计检索各自有 loading、empty、error、success、disabled 状态。

切片边界：

- 后续后台重构优先改布局和组件边界，不改变已确定接口契约。
- 新增后台能力前必须先写 DTO / endpoint 契约和 mock 验证。

## 9. 响应式规则

断点：

- `>= 1200px`：桌面工作台，左导航 + 主内容 + 右摘要。
- `900px - 1199px`：中等桌面，右摘要可变窄或进入抽屉。
- `640px - 899px`：平板，左导航折叠，摘要在主内容下方。
- `< 640px`：手机，单列布局，底部 sticky 操作条。

实现约束：

- 不按固定截图宽度写死布局。
- 不用 `white-space: nowrap` 强行撑开表格。
- 订单表格在小屏变为列表。
- 详情侧栏在小屏变为 `Drawer` 或独立详情页。

## 10. 页面级验收

每个页面完成时必须检查：

- loading、empty、error、success、disabled 状态齐全。
- 长产品名、长订单号、脱敏证件号不撑破布局。
- 桌面、平板、手机无横向滚动。
- 按钮文字不换行。
- 错误响应能展示统一错误提示。
- 截图与本文件提取的设计规则一致，不要求像素级一致。

## 11. 历史 Imagegen v2 / v1 简报和提取规则

生成模式：内置 `image_gen`。生成图保留在 Codex 默认目录，项目内版本已复制到 `docs/frontend/mockups/`。

购票工作台 v2 简报：

- 类型：React + Ant Design 桌面工作台。
- 范围：游客购票 MVP，不包含后台管理。
- 必须出现：左导航、顶部 API/DB/会话状态、四步流程、未实名门槛、票种列表、日期条、时段卡、右侧订单摘要、CSRF/session 安全提示。
- 避免：错误品牌、清江画廊、天气通知、退款承诺、营销 hero、深色发光、紫色渐变、卡片套卡片。

订单中心 v2 简报：

- 类型：我的订单桌面工作台。
- 范围：全部、待支付、已支付、已取消状态，以及订单详情契约错误态。
- 必须出现：状态筛选、订单号搜索、订单列表、右侧详情、票码区域、支付/取消动作边界、请求编号错误块、空态去购票。
- 避免：退款申请、后台功能、随机通知、泄露订单归属、不可读小字。

提取到实现的规则：

- 购票页优先处理“工作流层级”：步骤卡、选择区、摘要区三层要稳定，右侧摘要在桌面 sticky，平板以下下沉，手机隐藏为 sticky bar。

- 认证弹窗复现时保留现有表单校验和 E2E 占位符；安全目标是解释“后端会话读取身份、CSRF 自动携带、前端只提交必要实名字段”，不是新增认证能力。
- 后台页优先处理“运营密度”和“页面边界”：报表、订单和审计检索不是营销卡片，也不应该全塞在同一界面；每个子页都要有清晰标题、只读/状态变更边界和错误态。
- 后台 v3 复现时先处理页面结构：概览页只做流程和入口；报表页放总览、支付对账、产品和趋势；订单页放列表、批量核验、撤销核验、订单详情和退款动作；审计页放导出任务、核验审计、失败审计和退款审计；不为了贴图新增后端没有的字段。
- 后台订单抽屉复现时先处理操作层级：状态摘要在顶部，票项核验在退款之前，退款面板必须展示状态机路径和确认动作，审计日志收尾；所有字段仍以 DTO 和 mock data 为准。
- 后台移动端复现时先处理可用性：底部导航切换后台子页并保持 hash 可分享；报表指标可用双列压缩，订单必须使用移动卡片，表格只允许内部滚动。
- 后台动作按钮必须贴近状态机：核验只在可核验票项出现，整单退款只在 `PAID + PAID + 全部 UNUSED` 时可点。
- 安全提示使用小 Alert / Tag / 状态条，不使用大面积宣传式安全 section。
- 移动端使用卡片列表和 Drawer，不复用桌面表格视觉。
- 图片中的山水插画可以作为侧栏低对比识别，但不得影响首屏业务密度；实现可以先不加入真实图片资产。

不采用：

- 图片中的随机 IP、二维码、完整电话号码和证件号样式。
- 随机统计数字和不可由 API DTO 解释的字段。
- 固定分页、固定订单数和假库存文案。
- 任何不能在 `src/shared/api/types.ts` 找到来源的数据字段。
