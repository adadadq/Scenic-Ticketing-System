# 异步导出失败任务自动重试设计

日期：2026-07-02

## 问题

后台异步导出已经支持任务创建、worker 处理、失败任务手动重试和文件清理。当前 worker 遇到未预期异常会直接把任务标记为 `FAILED`，短暂文件系统抖动或偶发运行时错误需要管理员手动点重试，任务中心的恢复体验不够顺滑。

## 范围

- 为 `admin_export_job` 增加内部 `retry_count` 和 `max_retries` 字段。
- worker 对未预期异常导致的 `ADMIN_EXPORT_JOB_WORKER_FAILED` 自动重试一次。
- `AppError` 产生的业务/校验失败、未知导出类型或格式、手动中断不自动重试。
- 管理员手动 retry 仍支持 `FAILED -> PENDING`，并重置自动重试计数。

## 决策

- 自动重试只在任务仍处于 `RUNNING` 时通过状态条件更新，避免重复 worker 竞争。
- 自动重试成功入队时任务回到 `PENDING`，清空 `started_at`、`finished_at`、文件名和错误信息，不暴露中间失败给公开 DTO。
- 自动重试次数耗尽后，任务按现有失败机制落为 `FAILED` 并保留错误码和错误信息。
- `retry_count` 和 `max_retries` 暂不进入公开 DTO，避免前端在没有展示设计时依赖内部策略字段。

## 非目标

- 不实现指数退避、定时延迟重试或失败告警。
- 不接外部队列、分布式调度或生产监控。
- 不改变失败任务手动重试 API 的权限、CSRF 和错误码。

## 验收

- 未预期异常第一次失败时任务回到 `PENDING`，第二次失败后落为 `FAILED`。
- `AppError` 和 unsupported 失败不自动重试。
- 手动 retry 会清空文件元数据、错误信息并重置自动重试计数。
- schema、迁移、SQL 参数绑定和文档事实源覆盖新字段与状态机边界。
