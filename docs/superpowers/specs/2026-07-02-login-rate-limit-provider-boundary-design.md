# 登录限流 provider 边界

## 问题

当前游客登录和管理员登录限流都使用进程内内存实现，适合 MVP、本地联调和单实例课程项目演示。生产多实例如果需要全局限流，应迁移到 Redis、网关或负载均衡层，不能只改环境变量就误以为分布式限流已经接入。

## 范围

- 新增 `LOGIN_RATE_LIMIT_PROVIDER` 配置，默认值为 `memory`。
- 配置值会 trim 并转小写。
- 当前只支持 `memory`，任何未知 provider 都在配置校验阶段拒绝启动。
- 不改变现有游客登录、管理员登录、CSRF、session 或限流计数行为。

## 边界

- 不接入 Redis、Memcached、网关、负载均衡层或外部风控服务。
- 不改变当前限流 key：游客按客户端地址和手机号哈希，管理员按客户端地址和用户名哈希。
- 不改变 `RATE_LIMITED` 错误码或重试窗口。

## 安全要点

- 未实现的全局限流 provider 不能静默回退到进程内内存限流。
- 当前内存限流仍然只适合单实例或教学演示场景。
- 后续接入 Redis/网关前，需要重新建模容量、过期策略和跨实例一致性。

## 验收

- 配置测试覆盖默认 `memory`、大小写归一化和未知 provider 拒绝。
- 后端里程碑和安全清单明确全局限流尚未接入。
- 后端完整验证脚本通过。
