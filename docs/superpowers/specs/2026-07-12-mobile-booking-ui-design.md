# 移动端游客购票 UI 调试设计

日期：2026-07-12

## 1. 范围与目标

本设计是 `docs/frontend/frontend-blueprint.md` 的移动端购票专项补充。第一轮只处理游客购票主流程，不重做订单页、游客服务页或管理员后台。

目标：

- 让 390px 和 430px 手机宽度下的购票流程可读、可操作且无意外裁切。
- 保留现有 React、Ant Design、TanStack Query、接口契约和业务状态机。
- 消除桌面样式覆盖移动端样式造成的布局压缩，而不是继续追加末尾补丁。
- 保证 640–768px 平板布局不因手机修复而退化。

非目标：

- 不更改下单、登录、实名、常用出行人或 API 契约。
- 不新增 UI 库、路由库、移动端专用业务组件树或小程序式外壳。
- 不在第一轮重做“我的订单”“游客服务”和管理员页面。
- 不追求与 imagegen 草图逐像素一致。

## 2. 现状证据与根因

390×844 浏览器检查结果：

- 页面级 `scrollWidth` 与视口同为 390px，但这只是因为全局使用了 `overflow-x: clip`。
- 首张票种卡宽 284px，仍采用桌面规则 `72px minmax(0, 1fr)`。
- 隐藏插图后，自动布局把 `.ticket-card-main` 放进 72px 列；标题和标签并排后，标题实际只剩 24px。
- Ant Design `Sider` 收起后宽度接近 0，但 40px 的 zero-width trigger 仍覆盖页面左上区域。
- `Steps` 在手机端自动切换为纵向，步骤卡高度约 290px，挤占首屏。
- 移动端卡片 body 规则被后出现、选择器更具体的游客购票桌面规则覆盖，仍保留 26px 横向内边距。

根因是同一组件的基础样式、手机样式和后追加的游客购票视觉样式顺序互相覆盖，导致移动端契约没有最终所有权。修复应集中样式所有权，并以实测尺寸验证，不能依靠页面无横向滚动作为通过标准。

## 3. 方案选择

采用“重整响应式契约”方案：复用现有组件，只调整样式所有权和少量响应式组件参数。

拒绝：

- 只在 CSS 文件末尾继续追加零散覆盖：短期快，但会继续制造优先级冲突。
- 建立一套独立移动端购票组件：会复制选择、状态和提交逻辑，超出当前问题所需。

## 4. 设计读法与旋钮

Reading this as: 景区游客手机购票流程 for 现场或出行前购票的普通游客, with a 清晰、可信、紧凑但不拥挤的公共服务 visual language, leaning toward Ant Design plus existing water-pier tokens.

- `DESIGN_VARIANCE 3/10`：稳定、线性、易扫读。
- `MOTION_INTENSITY 1/10`：只保留状态反馈和浮层过渡。
- `VISUAL_DENSITY 5/10`：比桌面舒展，避免信息墙。

沿用水绿主色、橙色价格、8px 卡片半径和现有字体栈。不新增渐变光斑、营销组件或装饰性卡片。

## 5. 手机布局契约

手机范围为 `< 640px`；`640–899px` 继续使用平板堆叠布局。

从上到下：

1. 紧凑顶栏：保留会话/错误入口和侧栏触发器，但触发器必须位于明确的 44px 触控区域，不覆盖正文。
2. 景区标题区：高度约 150–170px；标题、说明与“我的订单”入口不重叠。
3. 紧凑步骤条：保持四步横排，只展示短标题，隐藏手机端描述；总高度控制在约 72–88px。
4. 票种区：单列卡片；卡片内容列使用 `minmax(0, 1fr)`，名称最多两行，标签和价格不得挤压名称到不可读宽度。
5. 日期与时段：日期条横向滚动；时段在 390px/430px 使用两列，只有极窄或长文案失稳时才降为单列。
6. 出行人区：常用出行人选择、姓名、证件号、手机号纵向排列，控件高度至少 44px。
7. 结算动作：隐藏桌面摘要卡，固定底部结算条展示已选摘要、总价和主动作。
8. 页面底部：预留结算条高度和 `safe-area-inset-bottom`，最后一个字段与按钮不能被遮挡。

页面滚动是唯一主滚动容器。日期条可以横向滚动；不引入额外纵向内滚动。

## 6. 组件与样式边界

保留：

- `VisitorAppShell`
- `BookingHeader`
- `BookingStepsCard`
- `TicketSelector`
- `DateSlotPicker`
- `PassengerAssignmentPanel`
- `OrderSummaryPanel`
- `BookingMobileActionBar`

允许的最小组件调整：

- 为 `Steps` 关闭会在手机端自动纵排的响应式行为，具体手机显示由 CSS 负责。
- 复用 Ant Design 现有 Sider trigger，通过游客壳移动端样式把它固定到顶栏的 44px 触控区域；不新增第二份导航入口或导航数据。

样式所有权：

- `app.css` 只负责壳、顶栏、侧栏/触发器和内容安全区。
- `booking.css` 负责购票标题、步骤、票种、日期时段、出行人和结算条。
- 每个移动端组件只保留一个最终覆盖区；删除或合并被后续规则反向覆盖的旧声明。
- 不通过增加 `!important` 或依赖现有全局 `overflow-x: clip` 掩盖组件宽度问题。

## 7. 状态、错误与无障碍

- loading、empty、error、disabled 和 fallback catalog 状态继续复用现有业务逻辑。
- 错误码、请求编号和长票名允许在字符边界合理换行，但不能逐字符形成窄竖列。
- 主按钮、导航触发器、日期与时段按钮的触控高度至少 44px。
- 保留语义按钮、表单标签、键盘 focus 和当前 `aria` 属性。
- 底部结算条不能遮挡浏览器缩放后内容，也不能阻止用户访问最后一个表单控件。

## 8. 实施顺序

1. 先建立 390px 失败基线：记录关键元素矩形、页面宽度和截图。
2. 整理游客壳的移动端侧栏触发器与内容安全区。
3. 修正步骤条方向和高度。
4. 统一票种卡手机网格与内边距所有权。
5. 调整时段、出行人字段和底部结算条。
6. 在 390、430、640、768px 回归，并复查桌面 1230、1440px。
7. 运行 lint、契约测试、E2E 和构建。

每一步只验证一个假设；若同一问题连续三次修复仍失败，停止叠加覆盖并重新检查组件结构。

## 9. 验收标准

- 390px、430px：页面无意外水平溢出，票种标题可读，标签与价格不碰撞。
- 390px：`.ticket-card-main` 不再落入固定 72px 列，标题可用宽度不低于 120px。
- 390px、430px：步骤条横排且总高度不超过 96px。
- 390px、430px：时段按钮保持可读的两列布局，按钮高度至少 44px。
- 390px、430px：出行人字段单列，输入内容与错误提示不被裁切。
- 390px、430px：底部结算条不遮挡最后一个内容块，并适配安全区。
- 640px、768px：平板堆叠正常，无桌面双栏残留。
- 1230px、1440px：桌面布局与现有视觉不发生明显退化。
- 最终通过 `npm run lint`、`npm run test:contract`、`npm run test:e2e` 和 `npm run build`。
