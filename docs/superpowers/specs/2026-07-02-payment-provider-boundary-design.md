# 支付 provider 边界

## 问题

当前游客支付和支付回调都属于模拟支付能力，适合 MVP、联调和课程项目演示。后续如果接微信、支付宝或其他真实支付渠道，不能让部署人员只改环境变量就误以为真实支付已经可用。

## 范围

- 新增 `PAYMENT_PROVIDER` 配置，默认值为 `mock`。
- 配置值会 trim 并转小写。
- 当前只支持 `mock`，任何未知 provider 都在配置校验阶段拒绝启动。
- 不改变现有支付接口、模拟回调、支付幂等、库存事务或 DTO。

## 边界

- 不接入微信、支付宝、Stripe、银联或其他真实支付 SDK。
- 不实现真实渠道回调、退款通知、渠道交易号或结算文件。
- 不改变当前 `POST /api/orders/{order_no}/pay` 和 `POST /api/payments/mock/callback` 的契约。

## 安全要点

- 未实现的支付 provider 不能静默回退到模拟支付。
- 模拟支付回调继续使用 HMAC、时间戳和事件幂等。
- 真实支付渠道接入前，生产环境仍需明确这是 mock provider。

## 验收

- 配置测试覆盖默认 `mock`、大小写归一化和未知 provider 拒绝。
- 后端里程碑和安全清单明确真实支付渠道尚未接入。
- 后端完整验证脚本通过。
