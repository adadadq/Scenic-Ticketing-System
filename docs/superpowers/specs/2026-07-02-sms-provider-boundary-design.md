# 短信 provider 边界

## 问题

当前游客登录是课程 MVP 的手机号直登演示流，没有发送短信验证码，也没有接入短信签名、验证码过期、发送频率、供应商回调或第三方短信账单。如果部署环境允许配置 `SMS_PROVIDER=aliyun`、`tencent` 或 `twilio` 静默通过，容易误以为真实短信登录已经上线。

## 范围

- 新增 `SMS_PROVIDER` 配置，默认值为 `disabled`。
- 配置值会 trim 并转小写。
- 当前只支持 `disabled`，任何未知短信 provider 都在配置校验阶段拒绝启动。
- 不改变现有游客登录、实名注册、CSRF、session 或登录限流行为。

## 边界

- 不发送短信验证码。
- 不新增验证码表、短信发送日志、供应商 SDK、回调接口或短信账单对账。
- 不改变 `POST /api/auth/visitor/login` 的请求 DTO、响应 DTO 或错误码。

## 安全要点

- 未实现的短信 provider 不能静默回退到手机号直登演示流。
- 当前手机号直登只适合 MVP、本地联调和课程项目演示。
- 后续接入真实短信前，需要重新建模验证码生命周期、发送频率、重放防护、短信轰炸防护和供应商错误脱敏。

## 验收

- 配置测试覆盖默认 `disabled`、大小写归一化和未知 provider 拒绝。
- 后端里程碑、API 契约和安全清单明确真实短信尚未接入。
- 后端完整验证脚本通过。
